Text2SQL 电商智能数据分析 Agent

项目负责人
自建 ECO-SQL-Bench v1.1（100 题） · Clean Baseline EX 90.0% · 967 passed
背景与问题

电商运营想查一个数据，要排队等开发写 SQL，一来一回效率很低；业务人员明明最懂问题，却被挡在数据库门外。

我的角色与关键决策

作为项目负责人，我决定用 LangGraph 编排「Schema 组织 → Few-shot 示例 → SQL 生成 → 校验 → 自动修复 → 执行」的完整链路；另一个关键决策是先建评测基准、再迭代优化——没有度量，就不知道改动到底有没有变好。

方案要点

安全层做足：只读连接、AST 语法校验、表与列存在性校验、结果量与重试次数上限，生成的 SQL 先过安检再执行。前端用 React + TypeScript 搭建查询工作台，结果以 ECharts 图表呈现。

成果
90.0%自建评测基准执行准确率（EX）
100 题ECO-SQL-Bench v1.1 评测集
18 个交付的前后端 API
FastAPILangGraphReact / TypeScriptEChartsSQLite评测体系

供应商重要性评估模型

数据分析
402 家企业 · 熵权法
背景与问题

一家建材企业要从 402 家供应商中选出核心合作对象，过去主要靠经验判断，缺少客观、可复核的依据。

我的角色与关键决策

我选择用熵权法做客观赋权，让指标权重由数据本身决定，避免主观打分带来的偏差。

方案要点

清洗近五年周度订货 / 供货时序数据，构建六项指标模型，用 Pandas / NumPy 完成建模与排序。

成果
402 家供应商样本 · 近五年时序数据
6 项指标熵权法综合建模
Top 50核心供应商筛选结果

并据此提出「战略合作 / 优先采购 / 备用」三级供应商管理体系建议。
